# design-claude-code-dynamic

Working repo for the Swovo design team's **Claude Code for Design** dynamic — the
hands-on session where the team practices using Claude Code as part of the design
workflow, from skill-building through prototyping to client-facing delivery.

## What's in here

- **`.claude/skills/larder-design-partner/`** — the skill used as the team's practice
  ground for the exercise. It plays a senior product design partner for **Larder**, a
  fictional desktop app for organizing recipes, so everyone has a real (if invented)
  product, personas, and business context to design against instead of a blank page.
- **`stakeholder-kickoff-transcript.md`** — the Larder V1 kickoff call transcript
  (Priya, Theo, and the outgoing contract designer), referenced by the skill for the
  reasoning behind decisions already made before today.
- **`hifi_prompt.txt`** — a reusable, tool-agnostic prompt template for turning a flow
  specification into a detailed hi-fi wireflow ready for design/dev handoff.
- **`Material/`** — real reference material from the NCMS project: design-team sync
  transcripts, and the UI slide decks used for client review.
- **Team member folders** (`Carlos/`, `Carol/`, `Eva/`, `Felipe E/`, `Felipe R/`,
  `Isis/`, `Mafe/`, `Nicolas/`, `Rosina/`, `Terra/`) — each person's own space to save
  their work from the dynamic (screens, flows, notes, exports).

## Using this repo during the dynamic

1. Work inside your own named folder — it keeps everyone's output separate and easy to
   review afterward.
2. Load the `larder-design-partner` skill at the start to get oriented on the product,
   personas, and open questions before sketching anything.
3. Commit as you go so progress is visible and recoverable, the same habit covered in
   the session's Git material.
